# MP3 播放器（ESP32-S3）

用 ESP32-S3 + ST7789 小屏 + TF 卡 + MAX98357A 做的一台桌面 MP3 播放器。
三个轻触按键 + 三个页面，全部功能靠"短按 / 长按"复用三个按钮。

> 这是个**边做边学**的嵌入式项目：从面包板搭模块开始，目标是走到自己在嘉立创画板打样。
> 代码注释写得比较啰嗦，因为很多结论是踩坑踩出来的。

当前版本：**v2.2 + v2.4**（中/日文歌名 + 封面）
编译体积：Flash 约 541 KB（41%）/ RAM 约 65 KB（19%）

---

## 功能

### 三个页面

| 页面 | 内容 |
|---|---|
| **页面1 播放详情** | 居中封面（140×140，真封面图）、歌名跑马灯、顶部状态行（状态圆点 + 曲目号 + 走秒） |
| **页面2 歌曲列表** | 7 行滚动列表，光标独立于"正在播放"，正在播的那行用暗绿底标出 |
| **页面3 设置** | 音量（0~100），值存 NVS 掉电不丢，SD 卡状态显示在这页 |

### 中文 / 日文

歌名和界面文字都能显示中文、日文。字库覆盖约 **21600 个字**：

| 区段 | 内容 |
|---|---|
| U+4E00–U+9FFF | CJK 统一汉字（中日共用，20992 字） |
| U+3000–U+30FF | CJK 标点 + 平假名 + 片假名（々 「 」 ・ お ユ） |
| U+FF00–U+FFEF | 全角符号（（ ） ？ ！） |
| U+2000–U+206F | 通用标点（— – " " …） |
| U+00A0–U+00FF | 拉丁字母补充（° × ÷） |

汉字取自 `simhei.ttf`，假名取自 `msgothic.ttc`（日文字形更准）。
查不到的冷门码位（比如 `ᐇ` U+1407 这种加拿大原住民音节文字）会画一个**空心豆腐块**，
而不是留一片空白 —— 至少让你知道那里有个字渲染不出来。

字库放在 SD 卡的 `font16.bin`（678 KB），**开机一次性读进 PSRAM**。
板子有 8 MB PSRAM，这样既不占 flash，以后想加大字号也有地方放。

### 封面

封面在 **PC 端就转好**，存成 `<歌名>.cov`（140×140 的 RGB565 原始数据，每张 38 KB）。
板子只做"一次顺序读 + 一次整块刷屏"（约 20 ms @ SPI 16MHz）。

这样固件里**不需要图片解码器**，也不会因为解码把音频卡爆。代价是每次往卡里加新歌，
要重跑一次 `prepare_sd.py`（见下面「上手」一节）。

封面来源优先级：**MP3 内嵌的 ID3 封面** → 同目录同名图片（`.jpg/.png/.bmp/.webp`）→ 没有就画空相框。

> 实测：大部分从云音乐软件下载的 MP3 里都**内嵌了 640×640 的 JPEG 封面**，
> 所以通常你什么都不用准备，脚本会自动抠出来。

### 按键

短按 = 按下再松开；长按 = 按住约 700ms（不用等松开，触发后继续按住会连发）

| | 页面1 播放详情 | 页面2 歌曲列表 | 页面3 设置 |
|---|---|---|---|
| **按钮1**（GPIO4） | 播放 / 暂停 | 播放光标那首 + 回页面1 | 返回页面1 |
| **按钮2**（GPIO15） | 上一首 ／ **长按→列表** | 光标上移 ／ 长按→返回 | 音量 +（长按连调） |
| **按钮3**（GPIO16） | 下一首 ／ **长按→设置** | 光标下移 ／ 长按→返回 | 音量 −（长按连调） |

> ⚠️ "长按进列表 / 进设置"是**隐藏手势**，界面上没有常驻提示。
> 第一次用请照着这张表按。

### 已经做到的细节

- **真·暂停**：不是"从头开始"，也不是"卡住最后一个音"。暂停时持续往 I2S 灌静音
  （ESP32 的 I2S 是 DMA 环形缓冲，停止填充会**重放最后一个缓冲**，听感就是最后一个音节卡死）
- **歌名跑马灯**画在整屏宽度的独立横条里，屏幕边界天然就是裁剪边界
- **UTF-8 安全截断**：列表页歌名放不下时按字符边界切并补 `…`，不会切出半个汉字
- **音频不断供**：界面重绘期间每画 12 个字就回来喂一次 `mp3->loop()`

## 硬件

| 部件 | 型号 / 规格 |
|---|---|
| 主控 | ESP32-S3-DevKitC-1（8MB Flash / 8MB PSRAM） |
| 屏幕 | 1.54" IPS，240×240，ST7789，SPI |
| 存储 | TF 卡模块（SPI），实测 32GB SDHC/SDXC |
| 音频 | MAX98357A（I2S 数字功放）+ 小喇叭 |
| 按键 | 3 个轻触开关 |

### 接线

**I2S 功放 MAX98357A**

| 功放引脚 | 接到 |
|---|---|
| BCLK | GPIO5 |
| LRC | GPIO6 |
| DIN | GPIO7 |
| VIN | **5V**（接 3.3V 声音会明显变小） |
| GND | GND |
| GAIN | 悬空=9dB；接 GND=15dB（不够响时用） |
| SD | 悬空=使能 |

> ⚠️ **喇叭的 `+`/`-` 只能接功放输出两端，绝不能把 `-` 接 GND**（BTL 桥接输出，接错会烧）。

**TF 卡（SPI）**

| 信号 | GPIO |
|---|---|
| CS | GPIO10 |
| SCK | GPIO12 |
| MOSI | GPIO11 |
| MISO | GPIO13 |
| VCC | 5V（模块板载 AMS1117-3.3） |

**ST7789 屏幕（SPI）**

| 信号 | GPIO | 备注 |
|---|---|---|
| SCL/SCK | GPIO12 | 与 TF 卡共用 |
| SDA/MOSI | GPIO11 | 与 TF 卡共用 |
| CS | GPIO9 | 独立片选 |
| DC | GPIO8 | |
| RES | GPIO14 | |
| BLK | 3V3 | 背光常亮，想调亮度需改接支持 PWM 的 GPIO |
| VCC | 3V3 | |

> 共用 SPI 的前提是 **CS 各自独立**。屏幕和 TF 卡分别用 GPIO9 / GPIO10。

**按键**：一端接 GND，代码用 `INPUT_PULLUP`，按下为 LOW。

| 功能 | GPIO |
|---|---|
| 播放 / 暂停 | GPIO4 |
| 上一首 / 长按列表 | GPIO15 |
| 下一首 / 长按设置 | GPIO16 |

**必须避开的引脚**：`0/3/45/46`（Strapping，上电决定启动模式）、`19/20`（USB D+/D-）、`26~32`（内部 Flash/PSRAM）。

## 编译与烧录

### 环境

- Arduino IDE 2.x
- ESP32 核心 **3.3.11**

### 依赖库（库管理器安装）

| 库 | 版本 |
|---|---|
| ESP8266Audio | 2.4.1 |
| Adafruit GFX Library | 1.12.6 |
| Adafruit ST7735 and ST7789 Library | 1.11.0（会一并装 Adafruit BusIO） |
| SD | ESP32 核心自带（**不要**装 Arduino 官方那个同名 SD 库） |
| Preferences | ESP32 核心自带 |

> ⚠️ `SD` 有两个同名库：Arduino 官方版（SdFat 1.x 血统）和 ESP32 核心版（ESP-IDF VFS/FATFS）。
> 本工程用的是**核心自带的那个**，因为它才有 `SD.begin(cs, spi, freq)` / `cardType()` / `cardSize()`。
> 如果你在 `Documents/Arduino/libraries` 里装过 Arduino 官方 SD，注意别让它抢走解析权。

### Arduino IDE 设置

| 项目 | 值 |
|---|---|
| 开发板 | ESP32S3 Dev Module |
| Flash Size | 8MB |
| PSRAM | OPI PSRAM（启用） |
| Partition Scheme | Default 4MB with spiffs |
| **USB CDC On Boot** | **Disabled** ← 用 UART 口看 `Serial` 输出时必须关 |
| 上传端口 | UART 口（本机是 CP2102N，识别为 COM4） |

> 用板载原生 USB 口会枚举出串口但烧录握手失败，请走 UART 口。

### 上手

#### 第 1 步：在 PC 上"备卡"

这步不做也能跑 —— 会退回 flash 里的 60 字小字库，只是歌名没中文、封面是空相框。

**默认是"一读一写"两个目录**，写在脚本顶部：

| 常量 | 默认值 | 放什么 |
|---|---|---|
| `DEFAULT_MUSIC_DIR` | `D:\software\Music` | 你的 mp3（平铺） |
| `DEFAULT_OUT_DIR` | `E:\Study\codes\Mp3\sd_ready` | 产出：`font16.bin` + 一堆 `<歌名>.cov` |

所以只要：

```bash
pip install pillow
python prepare_sd.py
```

或者**直接双击 `一键备卡.cmd`，什么都不输直接回车**。

跑完做一次拷贝：

```
D:\software\Music\          里的 .mp3
E:\Study\codes\Mp3\sd_ready\ 里的全部文件（font16.bin + 所有 .cov）
        ↓  都平铺进
SD 卡根目录
```

**想直接对 SD 卡操作**（卡插在电脑读卡器上，省掉拷贝这一步）：

双击 `一键备卡.cmd` → 输入卡盘符（比如 `F`）→ 回车。此时字库和封面会
**原地写进那张卡**，不可能出现"封面和歌名对不上"的问题。等价于：

```bash
python prepare_sd.py --music F:/ --out F:/
```

> 为什么要用 `F:/` 这种正斜杠写法？因为在 cmd 里写 `"F:\"` 会被 Windows 的
> 参数解析当成"反斜杠转义了引号"，Python 收到的是 `F:"`，整个参数就废了。

> ⚠️ **`.cov` 必须和对应的 `.mp3` 放在同一个文件夹（SD 卡根目录），名字一模一样。**
> 固件是这样找封面的：`春娇与志明.mp3` → 找同目录的 `春娇与志明.cov`。
> 分文件夹放它永远找不到。
>
> 播放器只扫 SD 卡的**根目录**，不支持子文件夹 —— PC 端脚本也只有一层，
> 跟固件行为保持一致。

| 参数 | 说明 |
|---|---|
| `--music` | 音乐目录（默认 `DEFAULT_MUSIC_DIR`） |
| `--out` | 输出目录（默认 `DEFAULT_OUT_DIR`） |
| `-i` / `--interactive` | 交互式提问（`一键备卡.cmd` 用的就是这个，回车=默认设置） |
| `--size` | 封面边长，**改了要同步改固件里的 `COVER_W` / `COVER_H`**（默认 140） |
| `--no-font` / `--no-cover` | 只做其中一件事 |

> ⚠️ 往文件夹里**加新歌之后要重跑一次**，否则新歌没有封面
> （歌名倒是能正常显示，因为字库是全量的）。

#### 第 2 步：烧录

1. 把 `.mp3` 放进 TF 卡**根目录**（最多扫 64 首）
2. 打开 `Mp3.ino`，按上表选好开发板设置，烧录
3. 开机后串口（115200）会打印 SD 卡状态、逐首曲目的文件名编码诊断、以及字库载入结果

> ⚠️ 本仓库名是 `MP3`，而主程序文件是 `Mp3.ino`。在 Windows / macOS（默认）上大小写不敏感没问题；
> 如果在**区分大小写的文件系统**（Linux）上 clone，Arduino IDE 会因为"文件夹名和 .ino 名不一致"打不开。
> 解决：把文件夹改名成 `Mp3` 再打开。

## 文件说明

```
Mp3.ino                   主程序（全部逻辑都在这一个文件里）
prepare_sd.py             PC 端"一键备卡"：生成中/日文字库 + 从 MP3 抠封面转 RGB565
一键备卡.cmd              双击运行的入口（纯 ASCII，中文提示由 Python 输出）
chinese_font.h            自动生成的 16×16 点阵字库（60 个界面字），不要手改
generate_chinese_font.py  上面那个字库的生成脚本
```

### 两套字库，别搞混

| 文件 | 存哪 | 内容 | 谁生成 |
|---|---|---|---|
| `chinese_font.h` | 编进 flash | **只含 60 个固定的界面字**（播放 / 音量 / 设置…） | `generate_chinese_font.py` |
| `font16.bin` | SD 卡 → 开机载入 PSRAM | **全量 21600 字**，中/日文歌名靠它 | `prepare_sd.py` |

界面文字优先查 SD 全字库，查不到再退到 flash 小字库。所以即使 SD 卡里没有
`font16.bin`，界面上的中文也照样显示，只是歌名会变豆腐块。

### 重新生成字库

改了界面文案、加了新字之后需要重新生成：

```bash
pip install pillow
python generate_chinese_font.py                    # 自动找常见中文字体
python generate_chinese_font.py D:/fonts/xxx.ttf   # 或指定字体
```

脚本会自动检查有没有生成为空白（字体里缺该字）的字形并告警。
Windows 下默认用 `simhei.ttf`（黑体，16px 下最清晰）。

### 串口诊断开关

`Mp3.ino` 顶部有两个开关：

| 宏 | 默认 | 作用 |
|---|---|---|
| `DEBUG_FILENAME_HEX` | `1` | 开机把每个文件名按**原始字节**打成 hex，并判断是不是合法 UTF-8、列出码点。用来排查中文/日文文件名编码问题 |

> 实测结论：**ESP32 核心自带的 SD 库返回的就是标准 UTF-8**，
> `春` 出来是 `E6 98 A5`（U+6625）、`お` 是 `E3 81 8A`（U+304A），
> 所以固件里**不需要任何编码转换**。这个诊断留着是为了以后换板子/换库时能快速复核。

## 已知限制

| 限制 | 说明 |
|---|---|
| **没有进度条** | 原来的进度是假的（`(elapsed/250) % 212`，每 53 秒回零，跟歌长无关），已移除。要做真需要解析 MP3 帧头算时长 |
| **只有一种字号** | 全局 16px。层级只能靠留白和亮度做，做不出"大标题 + 小注释"的排版 |
| **加歌要重跑脚本** | 歌名不受影响（字库是全量的），但封面是按歌生成的，加新歌要重跑 `prepare_sd.py` |
| **开机要等 1~2 秒** | 678 KB 字库在 SD 时钟 4MHz 下读进 PSRAM 的时间，屏幕会显示"载入字库" |
| **曲库上限 64 首** | 只扫根目录，不递归子目录，不排序 |
| **时长显示是走秒** | 顶部显示的是"已播了多少"，不是"总长多少" |
| **音质** | 赠品小喇叭有破音，待换 4Ω 3W / 8Ω 2W 并优化供电 |

## 踩过的坑

几个值得单独记的（完整记录留在本地笔记里，未上传）：

- **`SetGain()` 的 `4.0` 会溢出成 0**：`ESP8266Audio` 内部是 `gainF2P6 = (uint8_t)(f * 64)`，
  `f=4.0` 时 `256` 塞进 `uint8_t` 变 0 → 完全静音。而且精度只有 1/64。
- **暂停 ≠ 安静**：见上面"真·暂停"。环形缓冲 + DMA 的输出通道，"不写"不等于"输出静音"。
- **`.ino` 里自定义 `enum` 必须放在所有函数之前**：Arduino 会自动在第一个函数前插入函数原型，
  类型定义放在后面会直接编译失败。
- **两个同名 `SD` 库**：见编译依赖那一节。
- **点阵位序要对齐**：PIL 的 `"1"` 模式图 `tobytes()` 是按"每 8 像素一字节、高位在左"打包的，
  16×16 正好 32 字节。组装成 `uint16` 时是 `(byte0 << 8) | byte1`（**不是**小端直读）。
  这个搞错的话字库整体会变成乱码花纹。`prepare_sd.py` 里对此有注释。
- **Windows 上 `glob("*.mp3")` + `glob("*.MP3")` 会命中同一批文件**：文件系统大小写不敏感，
  结果是每首歌被处理两遍。要用 `iterdir()` + 小写后缀去重。
- **SPI 整块刷屏的缓冲要放内部 RAM**：`drawRGBBitmap` 最终走 SPI DMA，
  内部 RAM 才是稳妥的 DMA 源。字库（只被 CPU 逐点读）放 PSRAM 没问题，
  但封面缓冲（39 KB）特意留在内部 RAM。
- **cmd.exe 不能可靠地解析 UTF-8 批处理文件**：`.cmd` 里写中文会被当成命令报错。
  解法是 `.cmd` 保持纯 ASCII，所有中文提示交给 Python 打印
  （Python 在中文 Windows 的 cmd 里 stdout 编码是 gbk，控制台也是 gbk，正好对上）。
- **cmd 里 `--music "F:\"` 会被解析成 `F:"`**：反斜杠被当成转义引号，把后面的参数一起吞掉。
  写 `"F:/"` 就没事。
